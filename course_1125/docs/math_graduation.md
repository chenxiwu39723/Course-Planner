# 數學系113入學：畢業缺額與排課整合

## 網頁操作

1. 在「我的資料 → 畢業門檻與修課進度」選擇「數學系・計算與資料科學組・113入學」。
2. 按「載入77學分案例」，或匯入同結構的主系修課JSON。
3. 確認缺額、固定課與偏好，按「產生課表」。推薦課會附上可協助的畢業條件。

只保留統計學MA2011已完成的案例：77/128學分，尚差51。案例不含姓名、學號、成績分數或師培課。
JSON內`source_status`及`audit_categories`保留來源追溯；網站顯示的是規劃狀態，不修改學校成績。
網站目前匯入JSON，不提供PDF上傳，也不會向校方抓取學生個人資料。

## 系所／年度路由

- 規則識別碼：`math_datascience_113`。
- 僅適用113學年度入學、數學系計算與資料科學組；錯系所、組別、年度會回400。
- 其他系所不啟用規則時，仍使用原本通識／語言排課流程。
- `planner/graduation.py`讀取`data/graduation/`下的規則與去識別化案例。
- 畢業規則與分數計算全部由確定性程式處理；語言模型不判斷畢業資格。

## API

| 路由 | 輸入／輸出 |
|---|---|
| `GET /api/meta` | 新增`graduation_programs`，供下拉選單使用 |
| `GET /api/graduation/demo/math_datascience_113` | 回傳`student`，只供案例載入 |
| `POST /api/graduation/check` | `{program_id, student}` → `report` |
| `POST /api/schedules` | 原輸入加上可選`graduation: {program_id, student}`；回傳`graduation_report`與各課`graduation`說明 |
| `POST /api/free_slots` | 同樣接受`graduation`以保持候選與排課一致 |

`graduation`省略或為null時，不套用此系畢業規則。選了規則卻沒載入紀錄時，前端提示先載入，後端不默默套用別人的案例。

## 修課紀錄

以`math_datascience_113_demo.json`為格式範例。每筆課程含：

| 欄位 | 意義 |
|---|---|
| `course_id` | 六碼課號主碼，如MA2011；不使用開課流水號 |
| `term` | 四碼學年期，如1151 |
| `status` | passed / in_progress / failed / withdrawn |
| `credits` | 非負、有限數值 |
| `source_rule_code` | 個人主系審核分類，例如12101、13102；師培分類不接受 |
| `graduation_credit_eligible` | true才加進總學分；false不採計；null待確認 |
| `department_elective_eligible` | true才加進系所選修21學分；不依MA前綴直接認列 |

將在修課更新為passed，並不會自動把null採認欄位改成true。需要正式確認後再更新；目前不提供網站成績或採認編輯器，請修改JSON後重新匯入。

操行、體育與服務學習按學期紀錄計次；一般有學分課依主碼去重。不同學期重修的學分若不一致，或同學期紀錄重複，會要求人工確認。

## 與課程資料的對接

原型的`Course.id`是開課流水號，`Course.code`則是課號與班次。來源參考實作
[preprocess.js](https://github.com/zetaraku/NCU-Course-Finder-DataFetcher-v2/blob/master/src/helpers/preprocess.js)
將ClassNo前六碼視為課號，後綴視為班次。本次沒有改抓課程的方式，也沒有複製資料抓取器或NCU Course Finder網站。

新增`course_code_key()`將MA3111*、MA3111A、MA3111-A統一成MA3111。畢業比對用主碼，課表時間仍使用每班的流水號與times。

- 已完成與在修的主碼不再自動推薦；同課號其他班次也排除。
- 核心指定專題、缺少必修、已修自然科學系列的續修課可成為缺額候選。
- 大學部數學選修可列為「系所選修（採認待查）」候選，不會直接增加已完成學分；研究所數學課不因MA前綴自動加入。
- MA4071不自動替代指定核心專題；自然科學不同系列不可混搭湊6學分。
- 推薦課與替代課都附上缺額標籤；這是可能協助的條件，不是校方採認承諾。
- 同一張課表不選同課號兩個班；固定課衝堂或固定已完成課時會回400並提示修正。
- 數學系模式每張建議課表最多一門體育，通識推薦學分不超過目前缺額，核心專題不超過該組缺額。這些是避免推薦過量的規劃限制，不是宣稱學校有相同選課上限。

所有候選仍受原偏好中的通識領域、語言、時段、學分與空堂日篩選；設定過窄可能排不到缺額課。

## 學期與採認限制

目前repo課程清單為115-1（2330門）。缺額報告會列出「本資料學期未找到的缺額選項」，不捏造115-2開課或時間。範例課程模式另標示虛構資料。

分類不可直接相加；核心9學分與系所選修21學分的重疊採認尚待核對。來源尚缺113完整官方科目表、核心三選二的第三門課號、通識領域規則、學習護照最低時數、日法文與跨系選修採認等資訊。來源不明時保留待查，不把114年度規則當113年度正式依據。

## 隱私

個人JSON只保存在目前分頁的sessionStorage；檢查與排課時暫傳伺服器記憶體運算，不寫入檔案、資料庫或成績紀錄，不送入語言模型。內建去識別化77學分案例則是公開可載入的測試資料。不要將有姓名、學號、成績分數的原始文件放入repository。
