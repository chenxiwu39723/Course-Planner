# 階段 0：資料可行性檢查結果

- 檢查對象：中大課程查詢系統 <https://cis.ncu.edu.tw/>（新選課登記系統）
- 檢查學期：**115 學年第 1 學期**，學期代碼 `1151`（2026 Fall；由查詢頁學期下拉確認）
- 檢查時間：2026-10-14
- 檢查方式：`scripts/check_data_source.py`（實際請求一次，原始回應快取於 `data/raw/`）
- 系統狀態：頁面顯示「**非選課階段**」，公開瀏覽資料可正常取得

> 一句話結論：**API 目前可用，且本專案所需的全部核心欄位（時間、學分、教師、人數、教室、備註/限修、課程類別、通識領域、授課語言、課程大綱）都能在「未登入」情況下取得。** 另有一個意外收穫：限修條件除了自由文字備註外，還有**結構化的「分發條件」頁**可抓。

## 一、API 是否仍可用？

全部端點回應 `200`，可用。四個端點如下：

| 用途 | 方法 / URL | 參數 | 回應格式 |
|---|---|---|---|
| 系所／學院清單 | `GET /Course/main/query/byUnion` | 無 | HTML |
| 各系課程基礎資料 | `GET /Course/main/support/course.xml` | `id=<系所代碼>` | XML |
| 全校課程總表（分頁） | `GET /Course/main/query/byKeywords` | `query=true&d-49489-p=<頁碼>` | HTML |
| 單門課程大綱 | `GET /Course/main/query/byKeywords` | `serialNo=<5碼>&outline=<流水號>&semester=1151` | HTML |
| 單門課分發條件（限修） | `GET /Course/main/query/byKeywords` | `limit=<流水號>&semester=1151` | HTML |

- 本次實測：byUnion 取得 **90 個系所／單位**；course.xml 三個樣本系所（通識 61、語言中心 103、資工 72 門）皆正常；byKeywords 每頁 50 門、全校分頁。
- 與參考實作差異：參考實作（NCU-Course-Finder-DataFetcher-v2）**只抓** course.xml 的基礎欄位與 byKeywords 的「必/選修」，程式碼中把 `memo`（備註）、`classRooms`（教室）等欄位**註解掉了**。本專案最需要的備註/限修、教室、大綱都要**自行補抓**，資料來源已在本次確認可行。

## 二、可取得欄位表（對應 `planner/models.py` 規劃欄位）

| 模型欄位 | 可取得 | 來源端點 | 備註 |
|---|---|---|---|
| `id` / `code`（流水號 / 課號-班次） | ✅ | byKeywords td0、course.xml `SerialNo`/`ClassNo` | 流水號為全校唯一 5 碼，是兩來源的 **join key** |
| `name`（中/英文課名） | ✅ | byKeywords td1、course.xml `Title` | 中英文都有 |
| `teacher` | ✅ | 兩者皆有 | 多位教師以逗號分隔 |
| `credits` | ✅ | 兩者皆有 | |
| `times[(day, period)]` | ✅ | course.xml `ClassTime`（機器碼）＋ `ClassTimeAlt`（可讀，如「二78」） | 編碼見第四節 |
| `classroom` | ✅ | byKeywords td4 | 格式「一234/TR-A001 (教研大樓-A001)」含代碼＋大樓名 |
| `capacity`（人數限制） | ✅ | byKeywords td7、course.xml `limitCnt`/`admitCnt`/`waitCnt` | course.xml 另有已核定/候補人數 |
| `category`（選/必修） | ✅ | byKeywords td5 | 值為「選修」「必修」 |
| `notes`（備註） | ✅ | byKeywords td1 內的說明段落 | **自由文字**，如「零起點初級課程。大學部課程。[密碼卡:部份使用] [不開放初選]」 |
| 限修 / 分發條件 | ✅（額外收穫） | 分發條件頁 `?limit=<流水號>` | **半結構化**：優先順序＋條件說明，見第五節 |
| `ge_domain`（通識領域） | ✅ | 課程大綱「課程領域」欄 | 如通識 GS2064 → 「人文與思想領域」；語言課 → 「第二外語」 |
| `is_language` / `language`（授課語言） | ✅ | 大綱「授課語言」欄；byKeywords 可用 `crs_lang_no` 篩選 | 語言清單見第四節 |
| `syllabus_url` / `syllabus_text` | ✅ | 大綱頁（未登入可取得） | 含課程概述、教學目標、教科書、評量、週次 |
| `dept`（開課系所） | ✅ | byUnion 歸類、大綱「開課單位」 | |

> 課程查詢系統另提供 `passwordCard`（密碼卡：ALL/OPTIONAL/NONE）與 `dataTime`（資料更新時間）兩個額外欄位，可留作備用。

## 四、節次／星期／語言代碼（不自行假設，取自官方來源）

### 節次代碼完整清單（取自查詢頁 `day` 下拉選單）

```
1  2  3  4  Z  5  6  7  8  9  A  B  C  D  E  F
```

共 16 個，`Z` 為中午節，位於第 4 節與第 5 節之間。

### 節次 → 上課時間（取自中大課務組官方文件）

| 代碼 | 時間 | 代碼 | 時間 |
|---|---|---|---|
| 1 | 08:00–08:50 | 7 | 15:00–15:50 |
| 2 | 09:00–09:50 | 8 | 16:00–16:50 |
| 3 | 10:00–10:50 | 9 | 17:00–17:50 |
| 4 | 11:00–11:50 | A | 18:00–18:50 |
| **Z（中午）** | 12:00–12:50 | B | 19:00–19:50 |
| 5 | 13:00–13:50 | C | 20:00–20:50 |
| 6 | 14:00–14:50 | D | 21:00–21:50 |

> 來源：中大課務組「課程時間表使用說明」與「課程時間表」PDF（pdc.adm.ncu.edu.tw、lc.ncu.edu.tw）。
> ⚠ **待核對**：下拉選單另有 `E`、`F`（依序推為 22:00–、23:00–，屬極少用的深夜節次），官方 PDF 連結目前回 404，`E`/`F` 的確切時間在實作前應再向課務組最新版使用說明確認。節次**代碼清單**本身已由系統下拉選單直接確認，無需假設。

### 星期代碼（查詢頁 `week` 下拉）

`0=日 1=一 2=二 3=三 4=四 5=五 6=六`

### `ClassTime` 編碼規則（由樣本驗證）

- 以逗號分隔多個「星期＋節次」token，每個 token 固定 2 個字元：第 1 字為星期碼（0–6），第 2 字為節次碼（`1`–`9`,`Z`,`A`–`F`）。
- 例：`27,28` → `(二,7),(二,8)`，與 `ClassTimeAlt="二78"` 一致；`15,16` → `(一,5),(一,6)` ↔「一56」。
- 衝堂判斷即以 `(星期, 節次)` 集合是否相交決定（屬階段 2 的確定性程式，不交給語言模型）。

### 授課語言代碼（查詢頁 `crs_lang_no` 下拉）

`1 國語、2 英語、3 法語、4 台語、5 客語、6 日語、7 西班牙語、8 德語、9 部分英語、10 部份客語`

## 五、各項目可行性與無法取得／需加工項目

| 項目 | 狀態 | 作法 / 替代方案 |
|---|---|---|
| 備註（限修文字） | ✅ 自由文字 | byKeywords td1；階段 3 由語言模型解讀 |
| 限修條件（結構化） | ✅ 半結構化（優先順序＋說明） | 分發條件頁；**比純備註更可靠**，建議階段 3 優先解析此頁，備註作補充 |
| 課程大綱 | ✅ 未登入可取得 | 大綱頁；可作語意搜尋語料（階段 4） |
| 通識領域分類 | ✅ 精確值在大綱 | 大綱「課程領域」欄給精確領域（如「人文與思想領域」）；另可用 `核心通識課程`/`通識教育中心` 系所歸類與課號 `GS` 前綴做粗分 |
| 授課語言 | ✅ | 大綱「授課語言」欄；或用 `crs_lang_no` 篩選（10 種語言 → 最多 10 次請求即可全校標註） |
| 教室 | ✅ | byKeywords td4（代碼＋大樓名） |
| **全校課程量 / 抓取成本** | ⚠ 需注意 | 基礎資料走 course.xml（90 系所，約 90 次請求）＋ byKeywords 逐頁（每頁 50，抓到無下一頁為止）。**大綱與分發條件是「每門一個請求」**，全校上千門成本高 → 應離線批次並快取，必要時只對需要的課（如通識/語言）抓大綱 |
| 學生個人資料 | ❌ 不抓（依規範） | 帳號、成績、個人選課紀錄一律不取；使用者資料只存瀏覽器 |
